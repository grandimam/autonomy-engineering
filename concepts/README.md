# Concepts — learning path

Autonomy engineering is about systems that pursue objectives over time, not only models that generate responses.

Each substantial chapter should explain **what the concept is, why it exists, how to implement it, and how to verify it**, then link to reusable patterns, code, and real applications.

| Area | Guiding question |
| --- | --- |
| Objectives & planning | How does an outcome become concrete work? |
| Events & triggers | What starts, resumes, or repeats execution? |
| Tasks & workflows | How is work represented durably and advanced safely? |
| Execution & runtimes | How are actions delegated with bounded authority? |
| State & memory | What must persist across agents, runs, and restarts? |
| Verification & evaluation | What evidence proves the intended outcome? |
| Feedback & adaptation | How do observations change subsequent work? |
| Reliability & recovery | What happens when processes or dependencies fail? |
| Human oversight | When does the system require a person's decision? |
| Autonomous operations | How do these pieces become a continuously operating system? |
